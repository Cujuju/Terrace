# Perf work plan — frame drops, upload churn, p99 hitches (2026-09-14)

Source: `docs/perf-frame-drops-2026-09-14.md` (measured investigation; read first).
Method for every phase: implement → `typecheck` → probe-verify → commit (exact paths only)
→ append results to the investigation report. Standing rules apply throughout:
no new tests without per-session owner permission, `shared/` untouched unless a phase says so,
never `-A`/`git add .`, never touch the owner's live stack (`:2567`/`:5173`, default Chrome).

## Standard verification harness (all phases)

- Isolated stack recipe in `.perf-probe/` (server `:2678` on a fresh copy of
  `server/data/worlds/frostwick-hollows.db`, client `:5199`, throwaway Chrome over CDP).
- Standard poses: overview cam 80 (default) and far view cam ~270 via `.perf-probe/dolly.ps1`
  (verified through `stats()`; do NOT rely on seeded localStorage poses — ignored on boot, see report).
- Quiescence gate before every census (draws + tris stable <5% twice); record
  pixels + cam + draws + tris + programs with every number (pose rule).
- Instruments: far-view census + stats + profile (`.perf-probe/measureE.ps1` flow),
  sculpt load (`.perf-probe/measureH.ps1`). Post-Phase-A also use the fixed census script.
- HARD RULE (learned 2026-09-14, thunderstorm re-verify): the probe Vite server serves
  STALE transforms after client-source edits (no file watcher without TERRACE_WATCH; cache
  keyed by URL, fresh browsers do NOT help). Restart the probe Vite client after EVERY
  client-side edit before measuring, or the page runs old code and the numbers lie.

## Execution

- One background worker per phase, sequential (C After B lands, D items sequential — D1 and D2
  touch different files but share the verification harness and the report; run them back to back,
  not parallel). E can run alongside B (read-only + disjoint files; coordinate on report appends —
  one writer at a time for the report file).
- Each worker gets: this plan + the investigation report + the phase's acceptance lines.
  No servers/Chrome on owner ports; probe ports `:2678`/`:5199`/`:9333+` only.
- Liveness protocol (owner rule 2026-09-14, supersedes any older cadence): every worker
  appends timestamped lines to `.agent-stack/<phase>.log` as it works (item started, command
  launched, numbers as they land, blockers) — a tail-able live log — plus a heartbeat line
  at least every 5 minutes. Silence >10 min with no process/port/evidence movement = stuck;
  supervisor takes over from shared-tree state without asking.
- Final cleanup (end of last phase): delete `.perf-probe/` scratch (scripts, world copies, logs);
  keep `.census/*.json` evidence + both docs files. Confirm with owner before deleting.
