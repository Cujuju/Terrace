## 1. Facts (verified from source 2026-09-04, main 7a6eced)

  Frame loop: `viewport.onFrame(handler, phase)` with phases `'pose' | 'draw'`
  (`scene.ts:152`, `:481`). The host already owns a capture-phase `pointerdown` on the
  canvas (`host.ts:334`) — the natural autoplay-unlock gesture.
- Settings popup: `client/src/ui/Hud.tsx:453–460` renders `ControlsPanel` inside
  `.hud-settings-popup`. Persisted per-browser prefs follow `client/src/state/controlPrefs.ts`
  (module-scope Solid signals, versioned localStorage key).
- Assets: Vite serves `.wav`/`.ogg`/`.mp3` via `?url` imports out of the box (only `.glb`
  needed `assetsInclude`, `client/vite.config.ts`). Precedent for a plugin-owned asset:

- First consumers with ready-made events: `thunderstorm:strikes` (flat `[systemId,x,y,…]`,

- Tooling on this box: python3 + numpy 2.3.5; NO ffmpeg, NO sox. Placeholder assets are
  therefore WAV, generated by a checked-in script.
- Frame budget: ≥140 fps ≈ 7 ms (`docs/DESIGN.md`). Audio must do no per-frame JS mixing.

## 2. Design

Web Audio API is the engine; Three.js's `AudioListener` / `PositionalAudio` / `Audio`
are the wrappers (already a dependency — no new packages). Core owns the graph; plugins
only ask for sounds. Nothing on the wire changes and the server stays audio-free
("nothing gamey in core" — the server never knows a sound exists).

### 2.1 Graph (core, `client/src/audio/`)

```
plugin voices ──► bus gain (sfx | ambience | music) ──► master gain ──► destination
                                                          ▲
                              mute/volume prefs (audioPrefs.ts) ──┘
```

- One `AudioListener` attached to `viewport.camera`. Three.js updates its position and
  orientation from the camera's world matrix in `updateMatrixWorld`, so listener tracking
  costs nothing extra per frame.
- Three buses, each a `GainNode`, so a plugin never sets absolute loudness — it sets a
  gain relative to its bus, and the player owns the bus levels.
- One `AudioContext` for the page, created lazily and `resume()`d on the first user
  gesture (host's capture-phase canvas `pointerdown`, plus a one-shot `keydown` and
  `pointerdown` on `window` so a keyboard-first player also unlocks). Until unlocked,
  every play call is a silent no-op that logs nothing (autoplay refusal is the normal
  first-frame state, not an error). Ambience/music requests made before unlock are
  REMEMBERED and started on unlock, so the world is not silent until the first *sound*
  request after the click.
- Asset cache keyed by URL: one fetch + `decodeAudioData` per URL, shared by every plugin;
  concurrent requests for the same URL await one promise. Decoding is async and off the
  frame.
- Voice pool for one-shots: hard cap `MAX_SFX_VOICES` (32); when full, the OLDEST playing
  voice is stopped and reused. Per-frame cost is zero — Web Audio schedules on its own
  thread; JS only creates nodes at trigger time.
- Positional voices: `PositionalAudio` parented into a core-owned `Group` in the scene
  (NOT the plugin's layer — plugins' layers are for things they draw; audio nodes must
  survive a plugin's layer being cleared). Distance model `'inverse'`, `refDistance` and
  `maxDistance` in world units, named constants derived from `WORLD_UNITS_PER_BAND` scale
  in `client/src/config.ts` (no copied literals).

### 2.2 Capability (`ClientPluginCtx.audio`)

One namespaced member, mirroring how `layer`/`setSkyRig` are the only ways to touch
the scene:

```ts
readonly audio: PluginAudio;

interface PluginAudio {
  /** Fire-and-forget one-shot on the sfx bus. `at` (world cell coords) makes it positional. */
  playSfx(url: string, opts?: { at?: WorldPosition; gain?: number; playbackRate?: number }): void;
  /**
   * A looping layer this plugin fades toward `weight` (0..1, on the ambience bus).
   * One loop per (plugin, url); calling again just retargets the fade. weight 0 fades
   * out and releases the voice after the fade. Never positional: ambience is "the
   * world sounds like this", rain-under-camera not rain-at-a-cell.
   */
  ambience(url: string, weight: number): void;
  /**
   * SINGLE-CLAIMANT like setSkyRig: the first plugin to call claims the music bus, later
   * plugins are refused once and ignored. `null` stops with a crossfade.
   * Music is a loop with crossfade between tracks (two Audio voices, gains ramped).
   */
  setMusic(url: string | null): void;
}
```

- Every method is safe to call before unlock, before the join snapshot, and after
  detach (releases everything the plugin owns — the host's existing `track()` teardown
  pattern; voices do not outlive their plugin).
- Gains are ramped with `setTargetAtTime`/`linearRampToValueAtTime`, never stepped, so
  fades are on the audio thread and click-free.
- Detach releases the plugin's voices; a plugin's ambience/music does not outlive it
  (same containment as `layer` removal).

### 2.3 Player controls (`client/src/state/audioPrefs.ts` + settings popup)

Master volume (0..1) and mute, persisted like `controlPrefs.ts` (versioned localStorage
key, module-scope signals). Rendered as one row inside the existing settings popup
(`ControlsPanel` area of `Hud.tsx`). Defaults: volume 0.8, unmuted. Per-bus sliders are
NOT in scope (owner decision §7).

Justification for including any UI at all: a game that makes sound with no way to
silence it is user-hostile (preferences: user-hostile UIs are disqualified). A single
volume+mute is the minimum.

### 2.4 First consumers (proof the contract is right, not the sound design)

- `thunderstorm`: on each strike, `playSfx(THUNDER_URL, { at: strikeCell })` — positional,
  so a far strike is quiet. No delay-for-distance in phase 1 (§7).
- `rain`: each frame the rain plugin already knows which systems cover the camera cell;
  it calls `ambience(RAIN_LOOP_URL, weightUnderCamera)`. Retargeting each frame is one
  comparison when unchanged (host short-circuits identical weight).
- Music: NO consumer in phase 1. The bus and `setMusic` are built and exercised only by
  a dev switch (`?audioMusic=<url>` style dev query, matching the codebase's existing
  dev-switch conventions — agent verifies what those are and matches them). Owner picks
  the music source in §7.

### 2.5 Placeholder assets

`plugins/<name>/client/assets/*.wav`, generated by a checked-in
`scripts/audio-placeholders.py` (numpy; deterministic seed; ≤ 3 s sfx, ≤ 8 s loops,
22.05 kHz mono 16-bit to keep WAVs small). Header comment in each plugin names the file
as a PLACEHOLDER to be replaced by an authored asset. Real assets later are a file swap.

## 3. Phases

- **Phase 1 (this arc's first agent):** §2.1–§2.5 in full. One worktree
  `.claude/worktrees/audio-host`, branch `audio-host`. Report to
  `.claude/orchestration/briefs/audio-host-p1-report.md`.
- **Phase 2 (owner decided 2026-09-04):** procedural music. A `music` plugin claims the
  music bus and composes in real time on Web Audio oscillators (slow pad, sparse
  pentatonic melody, mood from daynight + weather via sibling-style structural
  subscription, never import). Contract change: the music claimant may either
  `setMusic(url)` (file) or receive a `MusicOutlet` (a GainNode on the music bus plus the
  context clock) to drive a generator; both go through the same claimant slot, so a real
  track later replaces the generator with one call. Scheduler wakes a few times a second
  via the audio clock lookahead pattern, zero per-frame work. Same worktree, fresh agent.
- **Phase 3 (later):** more sfx consumers (sculpt, fire, volcanoes, boats, monsters).

## 4. Rejected alternatives

- **Howler.js / Tone.js.** Both MIT and good, but Three.js already wraps Web Audio with a
  camera-tracking listener and positional voices; adding a second audio graph owner would
  duplicate exactly the part we need. Revisit if we hit a concrete gap (sprite sheets,
  format fallback). Also: no new dependency without asking (owner rule).
- **Plugins own their own `AudioContext`/nodes via `layer`.** Breaks the "everything via
  ctx" rule, lets two plugins create two contexts (browsers cap them), and no one owns
  the master volume.
- **Server-emitted sound events.** Adds wire traffic for something the client already
  knows from existing messages; violates "nothing gamey in core".
- **Runtime-synthesised placeholder sounds (no files).** Would skip building the asset
  path, which is the part that must be right for real assets later.

## 5. Residuals, named

- Browsers refuse audio until a gesture. Before the first click the world is silent; this
  is inherent and documented, not a bug.
- WAV placeholders are larger than OGG; acceptable for placeholders. Real assets should
  be OGG/Opus (Vite serves them with no config change).
- Safari's `PositionalAudio` panner is known to be costlier than Chrome's; with a 32-voice
  cap the worst case is bounded. Unverified on this project's target browsers.
